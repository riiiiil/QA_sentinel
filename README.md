# QA Sentinel 1.5

게임 커뮤니티에서 버그와 불만 신호를 수집하고 확인하는 한국어 웹 프로그램입니다. Python 서버, SQLite 저장소, 별도 빌드가 필요 없는 웹 대시보드로 구성됩니다.

## 실행

**본인 PC에서 사용하는 경우 START-HERE.md**에 운영체제별 실행, 기존 기록 이전과 PC 절전 설정 안내가 있습니다. 별도 서버나 Docker 없이 사용할 수 있습니다.

Python **3.11 이상**이 필요합니다. ZIP 안에서 실행하지 말고 소스를 폴더로 압축 해제하세요.

- Windows: `start.bat`을 더블클릭합니다.
- macOS / Linux: 폴더에서 `sh start.sh`를 실행합니다.
- 첫 실행은 인터넷에서 의존성을 설치합니다. 설치가 완료되고 requirements.txt가 바뀌지 않았다면 다음 실행에는 재설치하지 않습니다.
- 서버가 준비되면 브라우저가 자동으로 열립니다. 실행 창을 닫으면 서버와 자동 수집도 종료됩니다.
- 외부 사이트 없이 화면과 탐지를 시험하려면 Windows는 `manual-test.bat`, macOS/Linux는 `sh manual-test.sh`를 실행하세요. 자세한 절차는 **MANUAL-TEST.md**에 있습니다.

수동 설치를 원하면 다음 명령을 사용합니다.

macOS / Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

Windows PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python run.py
```

브라우저에서 **http://127.0.0.1:8000** 을 여세요. 포트를 바꾸려면 `run.py --port 8080`으로 실행합니다. 종료는 터미널에서 `Ctrl+C`를 누릅니다.

기본 서버는 로컬 컴퓨터에서만 접근하도록 실행됩니다. **본인 전용 24시간 운영**을 위한 Docker Compose, 영구 저장, 자동 백업과 SSH 터널 접속 구성은 **DEPLOY-PRIVATE.md**를 따르세요. 계속 실행되는 서버가 필요하며 웹 포트를 공개하지 않습니다. 서버가 종료되면 자동 수집도 멈춥니다.

## 첫 사용

1. 처음 열리는 **샘플 데이터** 화면에서 그래프, 피드백 상세, 사전, 임계치 변경을 확인합니다. 132개 샘플 게시글은 실제 커뮤니티 글이 아니며, 샘플 시각은 고정됩니다.
2. 우측 상단에서 **실제 수집**을 선택합니다. 실제 수집 DB는 처음에는 비어 있습니다.
3. **수집 채널 → 채널 추가**에서 대상 게시판을 등록합니다.
4. **키워드 사전**에서 우리 게임의 키워드와 동의어를 추가합니다.
5. **모니터링 설정**에서 시간창과 기준을 저장합니다.
6. **대시보드 → 지금 수집**을 눌러 첫 연결을 확인합니다. 실패하면 **수집 채널** 카드에서 원인을 확인합니다.

프로그램은 서버가 실행되는 동안 활성 채널을 약 15분마다 수집합니다. 수동 수집에도 채널별 최소 15분 간격을 적용합니다. 브라우저를 닫아도 수집은 계속되며, 화면은 자동 수집이 종료될 때 새 결과를 반영합니다. 수동 수집과 설정 변경은 즉시 반영합니다. 평상시 전체 데이터를 반복 조회하지 않습니다. 서로 다른 사이트의 채널을 최대 3개 병렬로 처리하고, 채널별 수집 시간은 120초로 제한합니다. 한 채널이 늦거나 실패해도 다른 채널을 처리합니다. 다수 채널에서는 실제 주기가 길어질 수 있습니다. 일시정지는 대기 중인 다음 채널부터 적용되며 이미 시작된 요청을 강제 취소하지 않습니다.

수집은 백그라운드에서 실행되고, 진행 중에는 화면에 완료 채널 수를 표시합니다. 수집 중에만 3초마다 가벼운 진행 상태를 조회합니다. 수집 시작·종료는 로컬 서버 알림 연결(SSE)로 전달하며 대기 중에는 연결 유지 신호만 주고받습니다. 팝업이나 입력창을 편집 중이면 자동 반영을 잠시 미루고 입력을 마친 뒤 반영합니다. 채널 응답을 기다리는 동안에도 시간창 만료 판정은 계속됩니다. 같은 데이터 폴더로 서버를 중복 실행하면 시작을 거부합니다.

## 지원하는 수집 방식

| 방식 | 등록할 주소 | 수집 내용 |
| --- | --- | --- |
| 디시인사이드 | `https://gall.dcinside.com/…/board/lists/?id=갤러리ID` 형태의 일반/마이너 갤러리 목록 | 목록의 제목, 작성 시각, 원문 URL |
| 아카라이브 | `https://arca.live/b/채널ID` 형태의 공개 채널 목록 | 목록의 제목, 작성 시각, 원문 URL |
| RSS / Atom | 공식 커뮤니티 등이 제공하는 공개 피드 URL | 피드의 제목, 작성 시각, 원문 URL |
| 공개 HTML / 공식 카페 | 목록에 제목과 정확한 작성 시각이 있는 공개 게시판 | CSS 선택자로 목록 행에서 제목·시간·링크를 읽음 |

HTML 채널은 목록의 게시글 행, 행 내부 원문 링크, **행 내부 작성 시각의 CSS 선택자 3개**를 입력합니다. 상세 페이지를 열지 않습니다. 기존 HTML 채널의 날짜 선택자가 상세 페이지 기준이라면 목록 행 내부 기준으로 수정해야 합니다. 이전 `body_selector` 설정은 사용하지 않습니다. 작성 시각은 `datetime` 속성, `title` 속성, 텍스트 순으로 읽습니다. 시간대 없는 한국어 게시판 날짜는 KST로 해석합니다.

수집 범위와 제약:

- 대상 게임과 실제 커뮤니티 주소가 제공되지 않아 특정 게시판과의 운영 연결은 사전 설정되어 있지 않습니다.
- 네이버 공식 카페 등 **로그인 또는 JavaScript 실행이 필요한 페이지는 기본 HTML 수집으로 읽을 수 없습니다.** 공개 RSS, 서버가 렌더링한 공개 페이지 또는 사이트별 정식 API 어댑터가 필요합니다. 로그인 차단을 우회하지 않습니다.
- HTML 방식(디시/아카라이브 포함)은 목록 페이지 최대 100행, RSS/Atom은 최신 50개를 처리합니다. 목록/피드 주소를 한 번 요청하고 상세 글과 다음 페이지는 요청하지 않습니다. HTTPS 리다이렉트는 검증·간격 제어 후 최대 4개 요청까지 따라갑니다. 대형 커뮤니티의 모든 글을 누락 없이 수집하는 페이지 순회·백필 기능은 후속 확장이 필요합니다.
- RSS/Atom 응답에 본문·요약이 포함되어 있어도 추출·저장하지 않습니다. 네트워크 응답 자체에는 피드 제공자가 넣은 내용이 포함될 수 있습니다.
- HTML 구조 변경, 차단 응답, 날짜 누락은 오류/부분 수집 경고로 표시합니다. 정상 글은 저장하고 잘못된 개별 글은 제외합니다. 전부 실패한 수집을 정상으로 표시하지 않습니다. 작성 시각을 수집 시각으로 바꾸지 않습니다.
- 원문 링크가 없는 피드 항목은 피드 주소로 대체하지 않고 제외합니다. Atom도 제목·작성 시각·링크만 읽습니다. CSS 선택자는 채널을 저장할 때 문법을 검증합니다.
- 공개 HTTPS와 기본 포트만 지원합니다. 요청 시 사설/루프백 IP를 차단하고 리다이렉트를 검사하며, 응답을 4MB로 제한합니다.
- 외부 사이트 이용 정책과 수집 권한에 맞는 주소를 등록하세요.

목록에 정확한 작성 날짜/시간이 없으면 해당 글을 경고와 함께 제외합니다. 본문이나 상세 날짜를 얻기 위한 추가 요청은 하지 않습니다. 제목에만 키워드가 있어야 감지되므로 이전 버전보다 감지 건수가 줄 수 있습니다.

## 필터와 감지 규칙

기본 대표 키워드는 **결제, 증발, 무한 로딩, 접속 불가, 팅김**입니다. 대표 키워드 아래에 동의어를 여러 개 입력할 수 있습니다. **제목만** 부분 문자열로 검색하며 Unicode 정규화와 영문 대소문자 무시를 적용합니다. 사전 변경은 기존 저장 글에도 적용됩니다. 이전 버전이 저장한 본문도 필터·검색·통계에는 사용하지 않습니다. 기존 DB의 본문은 자동 삭제하지 않고 보존합니다.

기본 시간창은 **최근 30분**이며, UI에서 5~1,440분으로 변경할 수 있습니다. 판정은 활성 채널에서 시간창 안에 **작성된 키워드 일치 고유 게시글**을 합산합니다.

| 상태 | 기본 기준 |
| --- | --- |
| 정상 | 3건 미만 |
| 주의 | 3건 이상, 5건 미만 |
| 위험 | 5건 이상 |

주의/위험 임계치는 화면에서 바꿀 수 있으며 위험 기준이 주의 기준보다 커야 합니다. 주의·위험 중 높은 단계를 우선합니다. 같은 채널의 같은 URL은 중복 저장하지 않으며 URL 조각, 일반적인 추적 파라미터를 제거합니다. 서로 다른 채널의 복사 글은 별도 글입니다. 다수 키워드가 일치해도 전체 게시글 수에는 한 번만 집계합니다.

키워드 순위는 키워드별 언급 게시글 수이므로 합계가 전체 고유 게시글 수보다 클 수 있습니다. 그래프는 선택 기간을 구간으로 나눈 **각 구간의 게시글 수**를 표시합니다. 상태 판정의 이동 시간창 합계와는 집계 범위가 다릅니다. 피드백 표의 상태는 해당 글에 일치한 키워드의 현재 언급량을 기준으로 표시합니다. 따라서 과거 게시글도 현재 키워드 상태를 보여줍니다.

시간창이 지나면 상태가 자동으로 낮아집니다. 채널을 비활성화하거나 삭제하면 해당 채널은 현재 감지에서 빠지며 기존 게시글은 보존됩니다. 삭제된 채널의 기존 게시글은 ‘삭제된 채널’로 표시됩니다.

## 감지 기록 / 웹훅

주의 또는 위험 상태에 **진입하거나 단계가 바뀔 때** 감지 기록을 생성합니다. 같은 상태가 유지되면 중복 기록을 만들지 않습니다. 기록에는 키워드별 언급량, 발생 채널, 시간창, 전체 언급 수, 관련 글 링크 최대 3개가 포함됩니다. 정상 회복 후 재발생하면 새 기록이 생성됩니다. 링크는 일치 키워드가 많은 글과 최근 글 순서로 선택합니다.

**디스코드·메신저 웹훅 전송은 요청대로 후속 개발 항목입니다.** 현재 앱은 메시지를 전송하지 않으며, 감지 기록에 미전송 상태를 표시합니다. 키워드 순위는 현재 언급량 기준이며, 이전 기간 대비 상승률 분석은 포함하지 않습니다.

## 피드백 확인과 데이터

- 피드백 목록에서 제목을 누르면 제목·시간·키워드를 봅니다. 본문은 수집하지 않는다고 안내합니다. 실제 수집 모드의 원문 버튼은 실제 URL을 새 창으로 엽니다.
- 제목 검색, 채널·키워드 드롭다운, 현재 키워드 상태 필터와 페이지 이동을 지원합니다. 조건을 함께 적용할 수 있으며 키워드 변경 시 첫 페이지부터 표시합니다. 사전에서 삭제한 키워드 필터는 자동으로 해제됩니다.
- ‘전체 CSV’는 현재 모드의 **필터링된 전체 저장 글**을 UTF-8 BOM CSV로 내보냅니다. 현재 화면의 검색 조건은 적용하지 않습니다. 수식으로 해석될 수 있는 셀을 방어 처리합니다.
- ‘JSON 가져오기’로 수집 엔진과 무관하게 탐지 규칙을 확인할 수 있습니다. UI에 예시가 있습니다. 입력은 제목, 시간대 포함 작성 시각, HTTPS URL의 배열입니다. 본문 필드가 있어도 저장하지 않으며 CSV에도 본문을 넣지 않습니다. 최대 1,000개이며 잘못된 입력은 배치 전체를 저장하지 않습니다.
- 데이터는 `.sentinel-data/live.sqlite3`, `.sentinel-data/demo.sqlite3`에 분리 저장됩니다. 샘플 사전/설정 변경은 실제 수집 설정에 영향을 주지 않습니다.
- 수동 테스트 모드는 별도 `.sentinel-test-data/`를 사용합니다. 외부 수집은 차단하며 일반 데이터 폴더를 읽거나 초기화하지 않습니다.
- 로그는 각 데이터 폴더의 `logs/qa-sentinel.log`에 저장합니다. 파일당 최대 2MB, 과거 파일 3개를 보관합니다. 1.0 데이터베이스는 처음 열 때 진단 컬럼을 추가하며 저장된 글을 보존합니다.
- 종료 후 `.sentinel-data/` 전체를 복사해 백업하세요. 위치를 바꾸려면 `QA_SENTINEL_DATA` 환경 변수를 설정합니다.
- 현재는 단일 서버 프로세스를 전제로 합니다. 대량 장기 운영에는 DB 조회의 페이지 처리, 보존 기간 정책, 별도 수집 작업 큐 확장이 필요합니다. `uvicorn --workers`로 수집 프로세스를 중복 실행하지 마세요.

## 검증

```sh
# Windows: test.bat 또는 start.bat --self-test
sh test.sh

# 자동 설치 없이 이미 준비된 Python으로 실행
.venv/bin/python run.py --self-test

# 실행 환경 진단: Windows는 start.bat --check
sh start.sh --check
```

새 앱의 자동 테스트 **90개가 통과**했습니다. 임계치 경계, 다중 키워드 중복 방지, URL 중복, 시간창 만료, 상태 전이 중복 억제, SQLite 영속성, 사전 변경 재필터링, 잘못된 입력의 원자성, RSS/Atom, 디시인사이드 및 아카라이브 HTML 해석, 수집 실패 기록, 15분 주기와 일시정지, API와 CSV를 검증합니다. 외부 커뮤니티 요청은 모의 응답으로 대체합니다. 추가로 실제 로컬 서버를 임시 데이터 폴더와 임시 포트에서 띄워 HTTP 접속, 정적 파일 제공, 위험 감지, CSV 응답, 종료 후 저장 데이터 유지까지 확인합니다.

확인하지 못한 부분: 실제 대상 커뮤니티에 대한 외부 수집, 브라우저 시각 검증, Windows 실기 실행. 이 버전은 로컬 실행 프로그램입니다. 이전 다운로드 페이지의 사용자 접속 문제는 해결되지 않았으며 프로그램 자체의 동작 검증과 구분합니다. JavaScript 구문 검사, 화면 생성 함수 검사와 Python 컴파일 검사는 통과했습니다.

기존 작업 폴더의 `scripts/critical_qa.py`는 다른 `sentinel` 엔진을 요구하는 별도 검증 도구입니다. 이번 앱은 `qa_sentinel` 패키지이며 기존 도구를 덮어쓰거나 해당 시나리오의 통과를 주장하지 않습니다. 새 앱 전체 검증에는 run.py --self-test를 사용하세요.

## 접속 또는 실행 문제 진단

| 증상 | 확인할 내용 |
| --- | --- |
| 서버가 열리지 않음 | `start.bat --check` 또는 `sh start.sh --check`의 오류를 확인합니다. |
| 8000 포트 사용 중 | `start.bat --port 8002` 또는 `sh start.sh --port 8002`로 실행하고 해당 포트로 접속합니다. |
| 브라우저 자동 실행이 안 됨 | 실행 창의 URL을 브라우저 주소창에 직접 입력합니다. HTML 파일을 더블클릭해서 여는 방식은 지원하지 않습니다. |
| 같은 데이터 폴더의 앱이 이미 실행 중 | 앞서 실행한 터미널에서 Ctrl+C로 종료합니다. `.server.lock` 파일을 지워 잠금을 우회하지 마세요. |
| 연결 상태가 ‘서버 연결 끊김’ | 실행 창이 열려 있는지와 로그를 확인합니다. 앱은 재연결을 시도합니다. |
| 수집 시 401/403 | 공개 접근 가능 여부와 사이트 정책을 확인합니다. 로그인 전용 카페는 별도 어댑터가 필요합니다. |
| 일부 글 수집 제외 | 채널 카드의 경고와 목록 행 내부 날짜 선택자를 확인합니다. 정상 글은 계속 저장됩니다. |
| 수동 테스트 모드에서 실제 수집이 안 됨 | 정상 동작입니다. 실제 수집은 `start.bat` 또는 `sh start.sh`로 일반 모드에서 실행합니다. |

사용 중인 서버의 상태는 `http://127.0.0.1:포트/api/health`에서 확인할 수 있습니다. 일반 모드 기본 포트는 8000, 수동 테스트 스크립트는 8001입니다.

## 1.2의 팝업·채널 변경

수집 채널 추가/수정은 기본 모달 대화상자를 사용합니다. 팝업 뒤 화면은 조작할 수 없고 배경 클릭·터치로 팝업이 닫히지 않으며 배경 스크롤도 막습니다. 닫기·취소 또는 Escape로 종료할 수 있습니다. 피드백 화면의 ‘모든 키워드’ 드롭다운에서 개별 키워드를 선택할 수 있습니다.

아카라이브 방식은 공개 채널의 목록 주소만 받습니다. `https://arca.live/b/game`처럼 입력하며 상세 글 주소(`/b/game/123`)는 등록하지 않습니다. 별도 CSS 입력 없이 목록의 제목, 작성 시각, 원문 URL을 읽습니다. 공지와 다른 채널 링크를 제외하며 원문 상세 페이지는 요청하지 않습니다. 로그인 또는 접근 제한이 있는 채널은 읽을 수 없습니다. 실제 아카라이브 접속은 아직 검증하지 않았으며 공개 페이지 구조가 바뀌면 어댑터 수정이 필요합니다.

## 요청 간격과 빈 화면 / 접근 제한 대응

같은 호스트의 채널은 순서대로 수집합니다. 디시인사이드/아카라이브는 하위 도메인도 같은 사이트로 묶습니다. 요청 시작 간격은 **디시인사이드 10~20초, 아카라이브 8~16초, 그 외 호스트 5~10초** 범위에서 무작위로 정합니다. 하한보다 빠르게 요청하지 않으며 네트워크 지연이나 사이트 대기로 간격이 더 길어질 수 있습니다. 수동 ‘지금 수집’도 모든 채널에서 최소 15분 간격을 지킵니다.

- 빈 화면인 HTTP 200 응답, 접근 확인 화면, HTTP 403/429/503은 정상 수집으로 처리하지 않습니다. 빈 화면만으로 소프트밴을 확정하지는 않습니다.
- User-Agent는 Chrome/Firefox/Safari 형식의 풀에서 수집 회차별로 무작위 선택합니다. 각 값에 `QASentinel/버전` 식별자를 유지하며 한 회차의 리다이렉트에서도 같은 값을 씁니다. 차단 시 User-Agent를 바꾸어 재요청하지 않습니다.
- 차단 의심 응답을 받으면 즉시 나머지 요청을 멈추고 같은 사이트의 모든 채널을 최소 30분 대기합니다. 다른 사이트는 계속 수집합니다.
- 반복되면 대기를 1시간 → 2시간 → 4시간 → 6시간까지 늘립니다. 유효한 Retry-After가 더 길면 우선하며 비정상적으로 긴 값은 30일로 제한합니다.
- 대기 시간은 SQLite에 저장되어 프로그램 재시작·채널 껐다 켜기·수동 수집으로 해제되지 않습니다. 리다이렉트된 목적지도 확인합니다.
- 대시보드와 채널 카드에서 대기 중인 채널과 재시도 시각을 볼 수 있습니다. 차단되기 전에 읽은 정상 글은 보존합니다.

이미 디시인사이드가 브라우저에서도 하얀 화면만 보인다면 **우선 해당 채널을 일시정지하고 반복 요청을 멈추세요.** **요청량과 속도를 낮춰도 IP 차단을 완전히 방지할 수는 없습니다.** 사이트의 정책, IP 평판과 다른 프로그램의 트래픽에도 영향을 받습니다. 이 기능은 기존 사이트 측 제한을 해제하지 않습니다. 30분은 앱의 최소 대기 설정일 뿐 사이트 차단의 해제 시간을 보장하지 않습니다. 일반 접속이 복구된 뒤 소량으로 확인하세요.

이 버전의 UI 로직 검사는 개발 환경에서 `node tests/test_ui.cjs`로 실행합니다. 팝업 배경 이벤트, 명시적 닫기, 키워드 드롭다운과 결합 필터, 아카라이브 선택, 삭제된 키워드 처리를 검사합니다. 실제 브라우저·터치 기기의 검증을 대신하지 않으며 프로그램 이용에 Node.js 설치는 필요하지 않습니다.

## 1.5의 화면 반영과 가독성

화면 상단은 마지막 화면 갱신 시각 대신 **최근 수집 종료 시각**을 표시합니다. 수집 중에는 시작 시각과 완료 채널 수를 표시하며, 수집 이력이 없으면 해당 안내를 보여 줍니다. 수집 종료 시각은 SQLite에 보관해 서버 재시작 후에도 유지합니다. 기존 버전 기록만 있다면 최근 채널 수집 시도 시각을 표시합니다. 실패/중단된 수집도 실제 종료 시각을 남깁니다.

대기 중에는 전체 데이터의 15초 폴링을 하지 않습니다. 수집 종료 알림 후 전체 데이터를 읽고, 수집 중에만 3초마다 진행 상태를 확인합니다. 알림 연결이 끊어지면 자동 재연결하며 누락된 종료 결과를 확인합니다. 검색 입력이나 팝업 편집을 마친 뒤 보류한 결과를 반영합니다. 샘플 모드는 알림 연결이나 진행 조회를 하지 않습니다. 시간창 통계는 화면에 반영된 스냅샷으로 표시되며 다음 수집 완료 또는 사용자 조작 시 최신 판정을 읽습니다. 서버의 시간창 판정은 계속 동작합니다.

기본 본문 16px, 표 14~15px, 보조 설명 최소 12px를 기준으로 글자를 키우고 남색 사이드바와 파란 주요 버튼을 적용했습니다. Windows의 맑은 고딕/Segoe UI 등 시스템 글꼴을 사용하므로 외부 폰트를 다운로드하지 않습니다. 주요 본문·보조문·버튼·상태 배지는 명암 대비 4.5:1 이상을 검사했습니다. 작은 화면에서도 수집 시각을 숨기지 않으며 긴 표와 그래프는 해당 영역 안에서 가로로 이동합니다.

JavaScript 갱신 제어 검사는 `node tests/test_refresh.cjs`, 기존 화면 동작 검사는 `node tests/test_ui.cjs`로 실행합니다. 자동 수집 간격 15분과 커뮤니티 요청 지연 설정은 그대로 적용됩니다. 업데이트 후 서버를 재시작하고 브라우저를 새로 여세요.
